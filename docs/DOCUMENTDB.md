# DocumentDB

One cluster per environment, one instance in it, private throughout.

## Variables used on this page

```bash
export PROJECT=mongo-dcu-pipeline
export AWS_REGION=us-east-1
export ENVIRONMENT=qa
export DOCDB_CLUSTER=$PROJECT-docdb-$ENVIRONMENT
```

| Variable | Example value | Where it comes from |
|---|---|---|
| `PROJECT` | `mongo-dcu-pipeline` | Fixed |
| `AWS_REGION` | `us-east-1` | Fixed |
| `ENVIRONMENT` | `qa` | `qa` or `prod` |
| `DOCDB_CLUSTER` | `mongo-dcu-pipeline-docdb-qa` | Derived: `$PROJECT-docdb-$ENVIRONMENT` |

**Generated, not chosen:**

| Value | Example shape | How it is produced |
|---|---|---|
| Cluster endpoint | `mongo-dcu-pipeline-docdb-qa.cluster-cxyz123abc45.us-east-1.docdb.amazonaws.com` | AWS assigns the `cluster-` portion at creation. `terraform -chdir=terraform/environments/qa output documentdb_endpoint` |
| Master password | 32 characters | `random_password` at apply time. Written to Secrets Manager, never printed, never in a variables file |

## Shape

| Setting | Value | Why |
|---|---|---|
| Instance class | `db.t3.medium` | The smallest DocumentDB offers, ~$0.077/hr - the largest single line in this project's hourly cost |
| Instances | 1 | A replica would double that line to protect 100 documents reseeded from a file in seconds |
| Engine | 5.0 | Matches the version-pinned local MongoDB container, so behaviour is the same from local to qa to prod |
| Backup retention | 1 day | The minimum. The data is regenerated by the reset playbook, not restored |
| Final snapshot | Skipped | The cluster is created and destroyed every session; snapshots nobody restores are storage that accumulates |
| Public endpoint | None | The security group accepts 27017 from the VPC range and nothing else. Everything that talks to it runs in the cluster |
| TLS | Enforced | See below |
| Storage encryption | On | Free, and there is no reason not to |

## TLS is on, and that has a consequence

DocumentDB enables TLS by default and the parameter group keeps it that way.
The cost is that a client must present the Amazon RDS CA bundle - so the
connection URI carries `tls=true` and `tlsCAFile`, and **the application image
must contain that bundle**:

```
mongodb://<user>:<password>@<endpoint>:27017/?tls=true&tlsCAFile=/etc/ssl/certs/global-bundle.pem&replicaSet=rs0&retryWrites=false
```

Three parts of that string are not obvious:

- **`tlsCAFile`** - the bundle is fetched at image build time from
  `https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem`. Without
  it, every connection fails certificate verification, and the error names the
  certificate rather than the missing file.
- **`replicaSet=rs0`** - DocumentDB presents itself as a replica set even with
  a single instance. A driver that connects without this talks to the instance
  directly and loses failover.
- **`retryWrites=false`** - DocumentDB does not support retryable writes, and
  `pymongo` enables them by default. Leaving it on produces a failure on the
  first write, not at connection time, which is a considerably worse place to
  discover it.

The alternative - setting the `tls` cluster parameter to `disabled` - would
turn off transport encryption on the database the whole pipeline exists to
modify, to avoid adding one file to an image.

## Query subset

Only what DocumentDB 5.0 actually supports, enforced by the validator before a
query is ever sent (`docs/QUERY-FORMAT.md`): `find`, `insertOne`/`insertMany`,
`updateOne`/`updateMany`, `deleteOne`/`deleteMany`, and aggregation limited to
`$match`, `$group`, `$sort`, `$project`, `$limit` and simple-form `$lookup`.

`$graphLookup`, `$text` and `$geoNear` are rejected by name, so the failure
explains what is unsupported instead of surfacing later as a DocumentDB error
with no context. The same subset is enforced in local dev, so a query that
passes locally passes in qa.

## Connecting

Nothing outside the VPC can reach the cluster - there is no public endpoint and
no internet gateway in the qa VPC. From a pod in the cluster:

```bash
# variable form
mongosh "$(aws secretsmanager get-secret-value --secret-id $PROJECT/$ENVIRONMENT/docdb \
  --region $AWS_REGION --query SecretString --output text | jq -r .uri)"

# expanded
mongosh "$(aws secretsmanager get-secret-value --secret-id mongo-dcu-pipeline/qa/docdb \
  --region us-east-1 --query SecretString --output text | jq -r .uri)"
```

## Reset

Drop the collection entirely, recreate the indexes, reseed the 100 documents -
one operation, runnable whenever test data has been mutated past usefulness.
Dropping rather than deleting documents means the indexes reset too.

Ansible playbook, and the `mongo-dcu-pipeline-11-documentdb-reset` Jenkins job.
Arrives in Phase 7 with the rest of the Ansible layer.

## Cost

`db.t3.medium` at ~$0.077/hr is the most expensive thing in this project after
the EKS control planes. Storage is $0.10/GB-month and backup storage is free up
to the cluster size. **Two environments running at once is $0.154/hr in
DocumentDB alone** - which is why prod is brought up for a promotion
demonstration and torn down with it, rather than left alongside qa.
